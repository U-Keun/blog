Claude Code의 Bash에서 `git`을 실행해서 생기는 비용을 아낄 수 있지 않을까 하는 생각에, `git`을 아예 실행하지 못하도록 hook을 만들어서 사용해 보았다. 하지만 그렇게 사용해보면서 약간의 문제가 생겼다.
#### 상태 스냅샷 스킬을 사용할 수 없게 되었다.
나는 Tickly에서 `tickly-state-5lines`라는 [[Areas/Claude CLI/1. 프로젝트에 Skills 적용해보기기\|skill]]로, 작업 시작마다 상태를 짧게 요약하여 고정해 두었는데, 이 스킬은 내부적으로 최근 커밋이나 변경량 같은 정보를 얻기 위해 read-only 명령을 쓰고 있었다. 예를 들면,
- `git log -3 --oneline`
- `git diff --stat`
내가 만들어 둔 훅은 `git`이라는 단어가 등장하는 순간 바로 차단했기 때문에, 스킬은 잘 호출이 되었지만, 정작 상태를 읽는 단계에서 막혀버렸다.
#### 정책 변경
상태 확인(조회)은 허용하고, 히스토리/원격/워크 트리를 바꾸는 명령은 차단하는 것으로 정책을 좀 더 구체적으로 변경했다. Claude는 상태를 읽고, 결정을 정리하고 실행 명령을 제시하도록 하고, 난 해당 명령을 실제로 실행하는 것이다.

내가 최종적으로 선택한 허용 명령은 다음과 같다.
- 허용(Allow: read-only)
  `git status`, `git log`, `git diff`, `git show`, `git branch`, `git remote`, `git rev-parse`, `git describe`
#### hook script
- `~/.claude/hooks/deny_git_bash.py`
```python
#!/usr/bin/env python3
import json
import sys
import shlex

# Allowed git subcommands (read-only)
ALLOW = {
    "status",
    "log",
    "diff",
    "show",
    "branch",
    "remote",
    "rev-parse",
    "describe",
}
...
def main():
    payload = json.load(sys.stdin)

    if payload.get("tool_name") != "Bash":
        return 0

    tool_input = payload.get("tool_input") or {}
    cmd = (tool_input.get("command") or "").strip()
    if not cmd:
        return 0

    # Only guard commands that start with `git`
    if not cmd.startswith("git"):
        return 0

    # Parse command safely
    try:
        parts = shlex.split(cmd)
    except Exception:
        # If parsing fails, be conservative
        sys.stderr.write("Blocked: unable to parse git command safely. Provide commands only.\n")
        return 2

    # parts[0] == "git"
    sub = parts[1] if len(parts) > 1 else ""

    # Allow read-only subcommands
    if sub in ALLOW:
        # Optional guard: keep diff output small unless explicitly requested
        if sub == "diff":
            # If user didn't specify any "short output" flag, still allow,
            # but you can choose to enforce it by blocking here.
            # We'll *allow* but encourage short output by not blocking.
            return 0
        return 0

    # Block everything else (mutating / network / risky)
    sys.stderr.write(
        "Git policy: do not run mutating git commands via tools.\n"
        "Allowed read-only commands: git status/log/diff/show/branch/remote/rev-parse/describe.\n"
        "For actions (commit/push/pull/merge/rebase/reset/etc.), output commands only.\n"
    )
    return 2

if __name__ == "__main__":
    raise SystemExit(main())
```
- `.claude/settings.json`
```json
{
  "permissions": {
    "allow": [
      "Bash(git status:*)",
      "Bash(git log:*)",
      "Bash(git diff:*)",
      "Bash(git show:*)",
      "Bash(git branch:*)",
      "Bash(git remote:*)",
      "Bash(git rev-parse:*)",
      "Bash(git describe:*)"
    ],
    "deny": [
      "Bash(git commit:*)",
      "Bash(git push:*)",
      "Bash(git pull:*)",
      "Bash(git merge:*)",
      "Bash(git rebase:*)",
      "Bash(git reset:*)",
      "Bash(git cherry-pick:*)",
      "Bash(git revert:*)",
      "Bash(git stash:*)",
      "Bash(git clean:*)",
      "Bash(git checkout:*)",
      "Bash(git switch:*)"
    ]
  },
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/hooks/deny_git_bash.py"
          }
        ]
      }
    ]
  },
  ...
}
```
>[!NOTE] 굳이 Claude Code에서 실행하지 않아도 되는 것으로 보이는 명령들도 차단해두었다.

위와 같이 설정을 하면서, skill은 규칙을 기억시키는 것이고, hook은 규칙의 경계선을 만들어 두는 것으로 이해했다. 아직 '명령 제시 -> 내가 실행'이 좋은 워크플로우인지도 고민이 필요하지만, 목적에 맞는 워크플로우를 잘 설정하는 방법에 대해 생각해볼 수 있었다.
