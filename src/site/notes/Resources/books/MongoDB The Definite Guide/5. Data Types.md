[[Resources/books/MongoDB The Definite Guide/1. Documents\|document]]는 JSON과 비슷한 형식으로 데이터를 가지는데, 기본적인 타입은 다음과 같다.
##### Boolean/Number/String
- Boolean : `true`/`false`
- Number: 셸은 기본적으로 64-bit floating-point로 보이며, 정수로 강제하려면 `NumberInt`, `NumberLong`을 쓴다.
- String: UTF-8 문자열을 저장한다.
```json
{ "x" : null }
{ "x" : true }
{ "x" : 3 }
{ "x" : "foobar" }
```
##### Date
MongoDB의 Date는 유닉스 epoch 기준 '밀리초(ms)'를 담는 64-bit 정수로 저장되며 타임존 정보는 저장되지 않는다.
```json
{ "x" : new Date() }
```
>[!NOTE] JavaScript에서 `new Date()`로 만들어야 `Date` 객체가 들어가고, 그냥 `Date()`를 호출하면 문자열이 되어 버려서 문자열/Date가 섞일 수 있다.
##### 정규표현식
쿼리에서 JS 정규식 문법을 쓸 수 있다.
```json
{ "x" : /foobar/i}
```
##### 배열
배열은 값으로 넣을 수 있고, 서로 다른 타입이 섞여도 되고, 중첩 배열도 가능하다.
```json
{ "things" : ["pie", 3.14] }
```

배열 원소를 기준으로 쿼리/인덱스를 만들 수 있고, 배열 내부 원소를 바꾸는 atomic update도 지원한다.
##### 중첩 document
문서 안에 문서를 값으로 넣을 수 있다. 관계형 DB에서 테이블을 나눠 join할 만한 정보를, MongoDB에서는 하나의 document에 묶어서 표현할 수 있다. 하지만 데이터 모델링에 따라 중복 데이터가 늘어날 수 있고, 수정 시에도 여러 document를 수정해야 할 수도 있다.
```json
{
    "name" : "John Doe",
    "address" : {
        "street" : "123 Park Street",
        "city" : "Anytown",
        "state" : "NY"
    }
}
```
>[!NOTE] 배열처럼 중복 document의 내부까지 들어가서 인덱스/쿼리/업데이트가 가능하다.
##### `_id`와 `ObjectId`
MongoDB의 모든 document는 반드시 유일한 `_id`를 가진다.[^1] `_id`는 어떤 타입이든 될 수 있지만, 기본값은 `ObjectId`다. `ObjectId`는 여러 머신에서 전역적으로 유일하게 만들기 쉽도록 설계된 기본 키인데, 자동증가 키처럼 중앙에서 순번을 맞추는 방식은 여러 서버/샤드에서 동기화 비용이 크기 때문에 이와 같은 키를 사용한다.

`ObjectId`는 12바이트로 구성되며, 보통 24자리 16진 문자열로 보인다. 앞 4바이트는 epoch 기준 초 단위 타임스탬프, 다음 5바이트는 랜덤 값, 마지막 3바이트는 카운터(시작값 랜덤)로 구성되어 있는데, 이러한 구조 때문에 삽입 순서에 가까운 정렬 특성이 생겨 인덱싱에 유리하다. 참고로, `ObjectId`에서 '생성 시각'을 추출할 수 있다.[^2]

문서 삽입 시 `_id`가 없으면 자동으로 추가된다. 이 작업은 서버가 할 수도 있지만, 보통은 클라이언트(드라이버)가 미리 생성해서 넣는 방식으로 이뤄진다.
##### Binary data
임의 바이트(UTF-8이 아닌 값 포함)를 저장할 때 쓰며, 셸에서 조작은 못 한다고 설명한다.
##### Code
문서나 쿼리에 임의 JavaScript 코드를 저장할 수 있는 타입이 있다.
```json
{ "x" : function() { /* ... */ } }
```

[^1]: 다른 [[Resources/books/MongoDB The Definite Guide/2. Collections\|collection]]끼리는 같은 값이 가능하다.
[^2]: 드라이버들이 보통 메서드를 제공한다.
