MonogoDB에서 데이터 변경은 원자적[^1]이다. 동시에 두 업데이트가 들어오면, 서버에 먼저 도착한 변경 사항 적용되고 그 다음 변경 사항이 적용된다. 그래서 충돌이 나도 [[Resources/books/MongoDB The Definite Guide/1. Documents\|document]]가 깨지진 않지만, 항상 마지막으로 적용된 변경 사항이 이긴다. 이것을 원하지 않는다면 나중에 알아볼 document versioning pattern을 고려해볼 수 있다.
#### document 교체
`replaceOne` 함수를 이용해 document를 교체할 수 있다. document 구조를 크게 바꾸는 작업을 할 때 유용하다.
```bash
test> db.users.find()
[
  {
    _id: ObjectId('695f8561a9ce805233af1ec0'),
    name: 'joe',
    friends: 32,
    enemies: 2
  }
]
test> var joe = db.users.findOne({"name" : "joe"});

test> joe.relationships = {"friends" : joe.friends, "enemies" : joe.enemies};
{ friends: 32, enemies: 2 }
test> joe.username = joe.name;
joe
test> delete joe.friends;
true
test> delete joe.enemies;
true
test> delete joe.name;
true
test> db.users.replaceOne({"name" : "joe"}, joe);
{
  acknowledged: true,
  insertedId: null,
  matchedCount: 1,
  modifiedCount: 1,
  upsertedCount: 0
}
test> db.users.find()
[
  {
    _id: ObjectId('695f8561a9ce805233af1ec0'),
    relationships: { friends: 32, enemies: 2 },
    username: 'joe'
  }
]
```
>[!NOTE] 교체할 document가 유일하지 않으면 문제가 생길 수 있다. 예를 들어, `{"name" : "joe"}`라는 조건을 만족하는 document가 여러 개인데, 해당 필터로 교체를 하려고 하면, duplicate key 에러로 교체가 되지 않는다. `_id` 같은 유일하게 document가 매칭될 수 있는 필터를 사용하는 것을 권장한다.
#### 변경 연산자 `$`
키를 추가하거나, 변경 또는 삭제할 때는 항상 `$set`, `$unset`, `$inc` 등을 사용한다.
- `$set` : 필드 값을 설정한다.[^2] 타입도 바꿀 수 있고, 중첩 document 내부[^3]도 수정이 가능한다.
- `$unset` : 필드 삭제
- `$inc` : 숫자 필드를 원자적으로 증가시킨다.[^2] 숫자 타입에만 가능하다.
```bash
test> db.analytics.find()
[
  {
    _id: ObjectId('695f8780a9ce805233af1ec1'),
    url: 'www.example.com',
    pageviews: 52
  }
]
test> db.analytics.updateOne({"url" : "www.example.com"},
| {"$inc" : {"pageviews" : 1}})
{
  acknowledged: true,
  insertedId: null,
  matchedCount: 1,
  modifiedCount: 1,
  upsertedCount: 0
}
test> db.analytics.find()
[
  {
    _id: ObjectId('695f8780a9ce805233af1ec1'),
    url: 'www.example.com',
    pageviews: 53
  }
]
```
##### 배열 변경 연산자
- `$push` : 배열 끝에 단일 값 또는 document를 추가한다.[^2]
	- `$each`로 여러 값 한 번에 추가할 수 있다.
	- `$slice`로 길이를 제한할 수 있다.
```bash
test> db.blog.posts.findOne()
{
  _id: ObjectId('695f9100a9ce805233af1ec2'),
  title: 'A blog post',
  content: '...'
}
test> db.blog.posts.updateOne({"title" : "A blog post"},
| {"$push" : {"comments" : {"$each" : [
| {"name" : "joe", "email" : "joe@example", "content" : "nice post."},
| {"name" : "bob", "email" : "bob@wxample", "content" : "good post."}
| ]}}})
{
  acknowledged: true,
  insertedId: null,
  matchedCount: 1,
  modifiedCount: 1,
  upsertedCount: 0
}
test> db.blog.posts.find()
[
  {
    _id: ObjectId('695f9100a9ce805233af1ec2'),
    title: 'A blog post',
    content: '...',
    comments: [
      { name: 'joe', email: 'joe@example', content: 'nice post.' },
      { name: 'bob', email: 'bob@wxample', content: 'good post.' }
    ]
  }
]
```
이외에도 중복을 방지하는 연산자[^4]나 제거하는 연산자[^5] 등이 있다.
#### `Upsert`(Update + Insert)
옵션 `{ upsert : true }`으로 매칭되는 document가 있으면 변경하고, 그렇지 않으면 해당 document의 표준 구조와 변경 내용을 합쳐서 새 document를 생성한다.

`$setOnInsert` 연산자와 함께 사용될 수 있는데, 삽입될 때만 생성하고 이후 변경되지 않는 필드에 주로 사용한다. `createdAt`이나 카운터 초기와 등에 사용한다.
#### 여러 document 변경하기
이전의 다른 함수들처럼 `updateMany` 함수를 사용하면 된다. 사용법은 `updateOne` 함수와 비슷하다.
```bash
test> db.users.insertMany([
| {"birthday" : "3/19/1992"},
| {"birthday" : "3/19/1992"},
| {"birthdat" : "3/19/1992"}])
{
  acknowledged: true,
  insertedIds: {
    '0': ObjectId('695f9853a9ce805233af1ec3'),
    '1': ObjectId('695f9853a9ce805233af1ec4'),
    '2': ObjectId('695f9853a9ce805233af1ec5')
  }
}
test> db.users.updateMany({ "birthday": "3/19/1992" }, 
| { "$set": { "gift": "Happy Birthday!" } })
{
  acknowledged: true,
  insertedId: null,
  matchedCount: 3,
  modifiedCount: 1,
  upsertedCount: 0
}
```
#### `findOneAnd*`
수정된 문서를 반환할 때, 이전에 사용되던 `findAndModify` 함수 대신 아래와 같이 3개의 함수를 사용한다. 문서 선택 + 상태 변경 + (변경 전/후 문서 반환)을 한 번에 원자적으로 처리한다. 큐/작업 할당 패턴에서 나올 수 있는 레이스 컨디션을 고려할 필요가 없다.
- `findOneAndDelete`
- `findOneAndReplace`
- `findOneAndUpdate`
>[!NOTE] 기본은 수정 전 document를 반환하는데, `{ "returnNewDocument" : true }` 옵션으로 수정 후 document를 반환하도록 할 수 있다.

[^1]: atomic
[^2]: 없으면 생성한다.
[^3]: `author.name` 같은 형태
[^4]: `$ne` + `$push` 또는 `$addToSet` + `$each`
[^5]: `$pop`(끝 또는 앞 원소 제거) 또는 `$pull`(조건에 맞는 원소 모두 제거)
