[[Resources/books/Learning LangChain/1. LLM Fundamentals with LangChain\|1장]]에서는 '프롬프트 → LLM → 응답' 형태를 구성해보았다. 이 구조는 모델이 이미 알고 있는 범위에서는 기대하는 답변을 얻을 수 있다. 하지만, LLM은 비공개 데이터와 최신 사건을 학습하지 못하기 때문에, 단순 프롬프트 기반 챗봇은 이 영역에서 쉽게 환각[^1]을 일으키며 프롬프트 개선만으로는 해결되지 않는다.

문서가 1~2페이지라면 매번 프롬프트에 전부 붙여 넣는 방식으로도 가능하지만 현실의 문서는 길다. 프롬프트 컨텍스트 길이는 제한되어 있고 전체 문서를 매번 넣을 수 없다. 매 질문마다 '가장 관련 있는 일부'만 고를 수 있어야 한다.

이것을 위해 컨텍스트를 사용하는 방법을 두 단계로 나눈다.[^2]
1. Indexing : 문서를 전처리해서, 질문이 들어올 때 관련 문서/구간을 쉽게 찾게 만드는 준비 작업
2. Retrieving : 인덱스에서 관련 조각을 실제로 가져와서 LLM 컨텍스트로 넣어 답변의 근거로 사용

이번 장에서는 Indexing 방법에 대해 알아보고, 다음 장에서 Retrieving을 다룬다.
#### Ingestion : 전처리 파이프라인
1. Extract : 문서에서 텍스트를 뽑는다    
2. Split : 텍스트를 관리 가능한 chunk로 쪼갠다
3. Embed : 텍스트를 컴퓨터가 다루기 좋은 숫자 vector로 바꾼다
4. Store : Embedding vector를 '빠르게 검색 가능한 저장소'에 넣는다
>[!NOTE] 의미가 비슷한 텍스트는 벡터 공간에서 가깝게 만들고, 가까운 chunk를 빠르게 찾는 것이 목적이다. 여기서, 숫자 벡터를 embeddings, 저장소를 vector store라고 부른다.
#### Embeddings
표현된 숫자 리스트(벡터)은 손실 표현[^3]이라서 원문 텍스트를 복원할 수는 없기 때문에, 일반적으로는 원문 텍스트와 Embedding vector를 함께 저장한다. 숫자 리스트가 되면 단어/문장을 수학적으로(?) 다룰 수 있게 된다.
##### LLM 이전의 Embedding
기본적인 아이디어는 문장들에서 모든 고유 단어 목록을 만들고, 각 문장에서 어떤 단어가 몇 번 등장했는지를 vector로 표현하는 것이다. 대부분의 단어는 해당 문장에 없으니 0인 값이 많아서, 키워드 검색이나 빈도 평균을 비교해 분류하는 작업에 유리하다. 하지만 단어가 겹치지 않으면, 의미가 비슷하더라도 다르다고 판단한다.
##### LLM 기반 Embedding
LLM 학습은 다음에 올 토큰을 맞추기 위해 문맥 속 의미 구조를 학습한다. 그것에 대한 모델의 이해를 숫자 표현(Embedding)으로 사용하는 것이다. 100~2,000 차원 정도의 부동소수점 vector로, 단어의 등장 빈도로 vector를 만드는 것과는 달리, 대부분의 값이 0이 아니다.[^4]
>[!NOTE] Embedding은 모델마다 좌표계가 다른 것으로 생각해야 한다. 하나의 시스템에서는 같은 Embedding 모델로 통일해야 한다.
##### 의미적 유사도
텍스트를 vector로 표현했다면, 각 vector를 고차원 공간의 점으로 볼 수 있다. 그리고 공간의 점이라면, 두 점 사이의 거리 또는 두 vector가 이루는 각도 등을 '의미가 비슷하다'고 판단하는 척도로 사용하자는 것이 핵심적인 개념이다. 실제로 많이 사용되는 척도가 cosine 유사도[^5]이다. 
#### Embedding 활용
1. Search : 쿼리와 가장 유사한 문서/문단 찾기
2. Clustering / Topic modeling : 가까운 점들끼리 군집 → 주제별 묶음
3. Classification : 새 문서를 기존 라벨(주제/스팸 여부 등)에 배정
4. Recommendation : 한 문서와 비슷한 문서 추천
5. Anomaly detection : 기존 분포에서 너무 동떨어진 문서 찾기
6. Averaging embeddings : 여러 조각 임베딩 평균 → '전체 의미' 대표 벡터로 쓰는 아이디어
7. 의미 공간에서의 산술 : 유명한 예) king – man + woman ≈ queen)
8. 멀티모달 임베딩 : 텍스트뿐 아니라 이미지/비디오/사운드도 벡터로 표현하는 모델
#### 문서를 텍스트로 변환하기 : `Document`
LangChain에서는 `.txt` 파일, 웹 페이지, PDF 파일을 `Document` 객체로 표준화하여 사용한다. `Document`는 다음과 같은 내용을 가진다 : 
- `page_content` : 추출된 텍스트
- `metadata` : 출처/페이지/라인 등 부가 정보[^6]
사용하려는 문서의 타입에 맞는 Loader를 선택하여 Loader 인스턴스를 만들고, `.load()` 함수를 호출하여 `List[Document]`를 얻는다.
##### `TextLoader`
아래의 스크립트를 실행하는 디렉토리에 `text.txt` 파일을 만들어두었다.
```python
from langchain_community.document_loaders import TextLoader

loader = TextLoader("./text.txt")
docs = loader.load()

print(type(docs[0]))
print(docs[0].page_content[:200])
print(docs[0].metadata)
# answer
<class 'langchain_core.documents.base.Document'>
Hello! I'm text!
{'source': './text.txt'}
```
이외에도 HTML을 텍스트로 파싱해서 `Document`로 만들어주는 `WebBaseLoader`와 `pypdf`를 이용해 PDF 파일을 파싱하여 `Document`로 만들어주는 `PyPDFLoader`가 있다.
#### 텍스트를 Chunk로 쪼개기
단순히 긴 텍스트를 일정 길이로 나누는 것은 검색 품질을 낮추거나, 질문과 문서의 연결성을 약하게 만들 수 있다. 의미적으로 연결된 문장 또는 문단은 한 덩어리로 있는 것처럼, 의미있는 단위로 텍스트를 쪼개야 한다.
##### `RecursiveCharacterTextSplitter`
1) 구분자(separators)를 중요도 순으로 둔다
	- 문단 구분: `\n\n`
	- 줄바꿈: `\n`
	- 단어 구분: ` `(space)
2) `chunk_size`를 만족하도록 큰 단위부터 자른 뒤, `Document`로 만든다.
	- 문단 기준 -> 줄바꿈 기준 -> 단어 기준으로 `chunk_size`에 맞게 분할한다.
잘린 각각의 chunk는 원래 문서의 `metadata`를 그대로 물려받고, 추가로 원문에서의 위치 정보 같은 추적 가능한 정보가 덧붙는다.
```python
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import TextLoader

loader = TextLoader("./test.txt")
docs = loader.load()

splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
)

splitted_docs = splitter.split_documents(docs)
print(splitted_docs)
# answer
[Document(metadata={'source': './text.txt'}, page_content="..."), ... ]
```
여기서 `chunk_overlap`은 chunk 사이에 일부를 겹쳐서 문맥 연결을 유지시키는 역할을 한다. 하지만 저장 비용과 중복이 늘어나는 것이기 때문에 적당한 크기로 잡아야 한다.

코드 언어나 마크다운 같이 구조가 '강한' 텍스트에는 언어별 splitter를 사용한다.[^7] 아래의 실습에서는 `create_documents()` 함수를 이용해서 문자열로부터 직접 `Document`를 만들도록 했다.
```python
from langchain_text_splitters import Language, RecursiveCharacterTextSplitter

PYTHON_CODE = """
def hello_world():
    print("Hello, World!")

# Call the function
hello_world()
"""

python_splitter = RecursiveCharacterTextSplitter.from_language(
    language=Language.PYTHON,
    chunk_size=50,
    chunk_overlap=0,
)

python_docs = python_splitter.create_documents([PYTHON_CODE])
print(python_docs)
# answer
[Document(metadata={}, page_content='def hello_world():\n    print("Hello, World!")'), Document(metadata={}, page_content='# Call the function\nhello_world()')]
```
>[!NOTE] `create_documents()` 함수는 두 번째 인자로 `metadata` 정보를 받아서 추가할 수 있다. 그러면 결과 chunk 각각에 동일한(또는 대응되는) `metadata`가 추가된다.
#### 텍스트 Embedding 생성하기
LangChain은 텍스트 embedding 모델(OpenAI, Cohere, Hugging Face 등)을 동일한 방식으로 쓰게 하려고 `Embeddings` 인터페이스를 제공한다.
- `embed_documents(texts: List[str]) -> List[List[float]]` : 여러 `Document`를 한 번에 embedding
- `embed_query(text: str) -> List[float]` : 질문 하나를 embedding
```python
from langchain_openai import OpenAIEmbeddings

model = OpenAIEmbeddings()

embeddings = model.embed_documents([
    "Hi there!",
    "Oh, hello!",
    "What's your name?",
    "My friends call me World",
    "Hello World!"
])

print(len(embeddings))          
print(len(embeddings[0]))       
print(embeddings[0][:8])
# answer
5
1536
[-0.020325319841504097, -0.007096723187714815, -0.022839006036520004, -0.026279456913471222, -0.037527572363615036, 0.02163294516503811, -0.006144568789750338, -0.008975640870630741]
```

[^1]: hallucination
[^2]: 이 두 단계가 합쳐진 접근이 Retrieval-Augmented Generation(RAG)이다.
[^3]: lossy.
[^4]: 두 개념을 Sparse <-> Dense 차이로 기억해도 좋을 것 같다.
[^5]: 값 범위는 -1 ~ 1이고, 1에 가까울수록 매우 유사하다고 판단한다.(각도 차이가 작다.)
[^6]: 추적이나 인용, 디버깅 등에 사용된다.
[^7]: 코드 등은 구조가 강해서 함수/블록이 찢어지는 것이 문맥을 더 해칠 수 있다. `chunk_overlap`도 사용하지 않는 것이 좋을 수 있다.
