LLM[^1] 어플리케이션은 '프롬프트를 어떻게 구성하느냐'와 '모델의 출력을 어떻게 처리해서 정확한 결과로 바꾸느냐'에 따라 좋은 어플리케이션인지, 그렇지 않은지로 나뉜다. 모델 자체보다 어플리케이션 계층이 더 어렵고, 이것이 제품의 품질을 결정한다. 그러므로 프롬프트 기법을 적절히 섞고, 잘 조합하여 운영을 잘 하는 것이 중요하다.
#### 왜 LangChain인가?
LangChain은 LLM 어플리케이션에서 자주 반복되는 패턴을 미리 구현된 형태로 제공한다. 예를 들면, 에이전트, 워크 플로우, 히스토리 요약 등이 있다. LangChain은 기본 템플릿으로 어플리케이션 개발을 시작할 수 있도록 도와준다.

또한, LangChain 컴포넌트[^2]는 표준 인터페이스를 사용하기 때문에, 모델 공급자 기능이 바뀌거나 요구 사항이 변해도 일부만 교체하는 방향으로 개발할 수 있다.
#### 실습 설정
먼저 Python 가상환경을 만들어서 실습을 진행했다. 아래는 가상환경 및 준비를 위해 사용했던 명령어이다.
```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -U pip
```

설치해야 하는 패키지는 책에 있는 것 그대로 사용했다.
```bash
pip install -U langchain langchain-openai langchain-community
pip install -U langchain-text-splitters langchain-postgres
```
##### OpenAI API 키 설정
OpenAI는 API 키를 환경변수 `OPENAI_API_KEY`로 두는 방식을 기본으로 안내한다. 나의 API 키를 [홈페이지](https://platform.openai.com/settings/organization/api-keys)에서 찾아서 아래와 같이 변수를 지정했다.
```bash
export OPENAI_API_KEY="sk-..."
```
>[!NOTE] 위의 명령은 현재 셸 세션에만 환경 변수를 지정해주는 것이라 특정 프로젝트(또는 디렉토리)에 들어가면 자동으로 사용하도록 `direnv`를 설치하여 사용하였다.
>```bash
>brew install direnv
echo 'eval "$(direnv hook zsh)"' >> ~/.zshrc
source ~/.zshrc
>```
>먼저 `direnv`를 설치하고, 프로젝트 루트에 다음과 같이 `.envrc` 파일을 생성한다.
>```bash
>cat > .envrc <<'EOF'
export OPENAI_API_KEY="sk-...your_key..."
EOF
>```
>`direnv allow` 명령으로 위의 설정 파일을 활성화시킬 수 있다. 그러면 해당 디렉토리에 들어갈 때마다 위의 환경 변수를 사용할 수 있다. `.envrc` 파일은 꼭 `.gitignore`에 추가해두도록 하자.[^3]
##### LLM / Chat Model : gpt-5-mini
책에 예제로 나와있는 gpt-3.5-turbo는 레거시로 분류되어서, 실용적이지 않을 것으로 판단되어 gpt-5 계열을 선택했다. 아래는 직접 API 호출을 해본 코드와 반환값 예제이다.
```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="gpt-5-mini", temperature=0.2)

print(model.invoke("The sky is").content)
# answer
…what would you like it to be?

If you meant a simple completion: “The sky is blue.”  
Quick science: daylight sky looks blue because air molecules scatter shorter (blue) wavelengths more than longer (red) — at sunrise/sunset the light travels farther so reds dominate.  

Want a poem, a joke, or a different completion (e.g., “the limit”)?
```
>[!NOTE] 어떤 모델을 사용할 지를 정하는 `model` 매개변수 외에도 공통적으로 사용하는 매개변수가 있다.
> - `temperature` : 생성할 때 다음 토큰을 얼마나 랜덤하게 뽑을 지를 조절하는 값이다. 숫자가 작을수록(0.1 ~ 0.2) 더 일관되고 예측 가능한 출력을, 숫자가 클수록(0.8 ~ 0.9) 더 다양하고 창의적인 출력을 반환한다.
> - `max_tokens` : 모델이 최대로 생성할 수 있는 토큰 수를 제한하는 값
#### OpenAI interface : role
OpenAI는 채팅에서 오가는 내용을 'role'(역할)로 구분한다.
- System role : 모델이 답변할 때 따라야 할 규칙/지침
- User role: 사용자의 질문과 사용자 제공 컨텐츠
- Assistant role: 모델이 생성한 응답
##### Message type
- `HumanMessage` : 사용자 관점 메시지 (user role)
- `AIMessage` : 모델 관점 메시지 (assistant role)
- `SystemMessage` : 시스템 지침 (system role)
- `ChatMessage` : role을 임의로 지정할 수 있는 메시지
##### HumanMessage 예제
```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

model = ChatOpenAI(model="gpt-5-mini", temperature=0.2)

prompt = [HumanMessage(content="What is the capital of France?")]
resp = model.invoke(prompt)

print(resp.content)
# answer
The capital of France is Paris.
```
##### SystemMessage 예제
```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage

model = ChatOpenAI(model="gpt-5-mini", temperature=0.2)

system_msg = SystemMessage(
    content="You are a helpful assistant that responds to questions with three exclamation marks."
)
human_msg = HumanMessage(content="What is the capital of France?")

resp = model.invoke([system_msg, human_msg])
print(resp.content)
# answer
The capital of France is Paris!!!
```
>[!NOTE] 실행 결과는 그때그때 다른 것 같다. 처음 위의 코드를 실행했을 때는 '!!!'만 출력되어서 요청이 더 구체적이어야 한 것 같았는데, 한 번 더 실행하니 원하는 답이 나왔다. `content`에 들어가는 내용도 꽤 구체적으로 들어가는 것이 좋을 것 같다.
#### `PromptTemplate`
문맥이나, 기본적인 출력 형식은 지정해서 프롬프트를 재사용할 수 있다.
```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import PromptTemplate

template = PromptTemplate.from_template(
"""Answer the question based on the context below. If the question cannot be answered using the information provided, answer with "I don't know".

Context: {context}

Question: {question}

Answer:"""
)

model = ChatOpenAI(model="gpt-5-mini", temperature=0.2)

prompt = template.invoke({
    "context": """ ... 컨텍스트 ... """,
    "question": " ... 질문 ... "
})

resp = model.invoke(prompt.to_string())
print(resp.content)
```
#### `ChatPromptTemplate`
`PromptTemplate`은 문자열 프롬프트를 만드는데, 위에서 이야기했던 role 기반으로 프롬프트를 사용할 수도 있다. 그것을 가능하게 하는 것이 `ChatPromptTemplate`이다.
```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

template = ChatPromptTemplate.from_messages([
    ("system", """Answer the question based on the context below. If the question cannot be answered using the information provided, answer with "I don't know"."""),
    ("human", "Context: {context}"),
    ("human", "Question: {question}"),
])

model = ChatOpenAI(model="gpt-5-mini", temperature=0.2)

prompt = template.invoke({
    "context": """The most recent advancements in NLP are being driven by Large Language Models (LLMs). Developers can tap into these models through Hugging Face's transformers library, or by utilizing OpenAI and Cohere's offerings...""",
    "question": "Which model providers offer LLMs?"
})

resp = model.invoke(prompt)
print(resp.content)
# answer
Hugging Face, OpenAI, and Cohere.
```
이렇게 하면 지침은 `SystemMessage`로 유지되고, `context`와 `question`은 `HumanMessage`로 동적으로 채워넣게 된다. 위의 방식은 챗봇/대화형 앱에 유리하다.
#### 특정 포맷으로 출력 받기
LLM을 앱에 붙일 때, LLM의 결과를 프론트엔드로 보내거나, DB에 저장하는 등 일반 문자열보다 기계가 읽기 쉬운 형태(JSON/CSV/XML)로 사용해야 할 수도 있다.
##### JSON 출력
원하는 JSON 형태를 스키마(구조/타입/필드명)를 정의하고, LangChain에게 그 스키마를 전달한다. 답변에 대해서도 전달했던 스키마로 검증한 뒤에 통과시킨다.
```python
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field

class AnswerWithJustification(BaseModel):
    answer: str = Field(description="The answer to the user's question")
    justification: str = Field(description="Justification for the answer")

llm = ChatOpenAI(model="gpt-5-mini", temperature=0)
structured_llm = llm.with_structured_output(AnswerWithJustification)

resp = structured_llm.invoke("What weighs more, a pound of bricks or a pound of feathers?")
print(resp)
# answer
answer='They weigh the same — a pound of bricks and a pound of feathers each weigh one pound.' justification='By definition both amounts are one pound, so their weight is equal. (Note: feathers take much more volume and, if measured in air, buoyancy can make their apparent weight very slightly less than the bricks, but in the usual riddle sense they are equal.)'
```
코드를 보면 `with_structured_output` 함수는, 위에서 정의한 `AnswerWithJustification` 스키마를 JSON Schema로 변환해서 전달하고, 모델이 반환한 결과를 `AnswerWithJustification` 스키마로 검증한다. 
#### Output Parser
CSV로 리스트/표 형식을 넘기거나, XML로 내보낼 수도 있다. Output Parser를 이용해서 형식 지시문을 제공하거나, 규칙에 맞게 잘라서 list나 dictionary 구조로 바꿀 수 있다. 
- `CommaSeparatedListOutputParser`
```python
from langchain_core.output_parsers import CommaSeparatedListOutputParser

parser = CommaSeparatedListOutputParser()
items = parser.invoke("apple, banana, cherry")
print(items)
# answer
['apple', 'banana', 'cherry']
```
- `JsonOutputParser`
```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import JsonOutputParser

# 1) 파서 생성 (dict로 파싱)
parser = JsonOutputParser()

llm = ChatOpenAI(model="gpt-5-mini", temperature=0)

# 2) 프롬프트: JSON 출력 규칙
prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant. Return ONLY valid JSON. No extra text, no markdown, no code fences."),
    ("human", """Follow this JSON schema exactly:
{{
  "answer": string,
  "justification": string
}}

Question: {q}
"""),
])

# 3) 실행: prompt -> llm -> parser
chain = prompt | llm | parser
result = chain.invoke({
    "q": "What weighs more, a pound of bricks or a pound of feathers?"
})

print("DICT:\n", result)
print(result["answer"])
print(result["justification"])
# answer
DICT:
 {
	 'answer': 'They weigh the same.', 
	 'justification': 'A pound is a unit of weight, so one pound of bricks and one pound of feathers each equal one pound. (Note: feathers occupy much more volume and experience more air buoyancy, which can make their apparent weight very slightly different in air, but by definition one pound equals one pound.)'
}
They weigh the same.
A pound is a unit of weight, so one pound of bricks and one pound of feathers each equal one pound. (Note: feathers occupy much more volume and experience more air buoyancy, which can make their apparent weight very slightly different in air, but by definition one pound equals one pound.)
```
#### 조립하기
##### Runnable interface
지금까지 살펴본 구성요소들(모델, 프롬프트 템플릿, 출력 파서)은 공통적으로 같은 함수를 제공한다.
- `invoke(input) -> output` : 단일 입력을 단일 출력으로 반환
- `batch([input,..]) -> [output,...]` : 여러 입력을 한 번에 처리
- `stream(input) -> output` : 출력이 생성되는 대로 스트리밍
- 위의 실행에 대해 재시도(retry), 폴백(fallback) 등의 유틸리티를 붙일 수도 있다.
```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="gpt-5-mini", temperature=0.2)

completion = model.invoke("Hi there!")
print(completion.content)

completions = model.batch(["Hi there!", "Bye!"])
print([c.content for c in completions])

for chunk in model.stream("Bye!"):
    print(chunk.content, end="", flush=True)
print()
# answer
Hello! How can I help you today?
['Hello! How can I help you today? \n\nI can answer questions, help with writing or editing, generate ideas, explain things, debug code, summarize text, or assist with planning tasks — whatever you need.', 'Goodbye! Take care — feel free to come back anytime.']
Goodbye! Take care — feel free to come back anytime if you need help.
```
>[!NOTE] Python에서는 위의 메서드에 대한 비동기 버전인 `asyncio`도 제공한다.
##### Imperative
내가 실행 순서를 직접 써서 조립하는 방식을 말한다. 코드로 프롬프트를 만들고, 그 결과를 모델에 넣고, 필요하면 중간에 `if`/로그/후처리를 끼우고, 최종 결과를 반환하도록 하는 것이다.
```python
from langchain_core.runnables import chain
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

template = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant."),
    ("human", "{question}"),
])
model = ChatOpenAI(model="gpt-5-mini", temperature=0.2)

@chain
def chatbot(values):
    prompt = template.invoke(values)
    resp = model.invoke(prompt)
    return resp

chatbot.invoke({"question": "Explain embeddings briefly."})
```
당연하지만, 로직을 커스텀하기 좋고, 중간에 로그를 남기도록 코드를 작성하면 디버깅하기도 쉬울 것이다. 하지만, LangChain이 제공하는 스트리밍이나 비동기 기능을 넣으려면 직접 추가해줘야 한다.
##### Declarative
무엇을 연결할지 선언만 하고, 어떻게 실행할지는 LangChain에 맡기는 방식이다. 파이프라인을 선언하면 LangChain이 내부적으로 작업을 알아서 수행한다.
```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

template = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant."),
    ("human", "{question}"),
])
model = ChatOpenAI(model="gpt-5-mini", temperature=0.2)

chatbot = template | model

chatbot.invoke({"question": "Explain embeddings briefly."})
```
##### Imperative vs Declarative
###### Imperative가 유리한 경우
- 중간에 `if`/`for` 같은 일반 로직이 많다
- 모델을 여러 번 호출하면서 상태를 관리한다
- 외부 시스템(DB, 파일, API)과 섞인 절차가 많다
- 디버깅을 줄 단위로 하고 싶다
###### Declarative(LCEL)가 유리한 경우
- “입력 → 프롬프트 → 모델 → 파서” 같은 전형적인 체인
- 스트리밍/`async`를 신경쓰고 싶지 않다
- 나중에 구성요소를 교체(`prompt`/`model`/`parser`)할 가능성이 크다
- 관찰/트레이싱/실험(프롬프트 버전 관리 등)을 체계화하고 싶다
>[!NOTE] 큰 구조에는 Declarative로, 세세한 부분은 Imperative 방식으로 구현하는 것을 추천한다고 하는데, 이것은 실제로 서비스를 만들어보면서 이해해봐야 할 것 같다.
