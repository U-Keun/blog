[[Resources/books/Learning LangChain/2. Indexing Your Data (1) Ingestion & Embeddings\|이전 장]]에서는 문서를 전처리하고 chunk로 나눈 뒤, embedding을 만들어 vector store에 저장하는 흐름을 다뤘다. 이번 장에서는 사용자의 쿼리를 입력으로 받아 가장 관련 있는 문서 chunk를 효율적으로 검색(retrieve) 하고, 이를 LLM 프롬프트의 컨텍스트로 구성하는 방법을 다룬다.
#### Retrieval-Augmented Generation(RAG)
RAG는 LLM이 답변을 생성할 때, 모델이 학습한 지식만 사용하지 않고 외부 데이터 소스에서 가져온 관련 문서를 컨텍스트로 제공해 더 정확하고 근거 있는 답을 만들게 하는 기법이다. 일반적인 RAG 파이프라인은 다음 흐름으로 정리할 수 있다 :
- 사용자 질문을 embedding으로 변환한다.
- embedding(및 조건/필터)을 기반으로 vector store 등에서 유사한 문서 chunk를 검색한다.
- 검색 결과를 컨텍스트로 프롬프트에 포함해 LLM에 전달한다.
- LLM은 제공된 컨텍스트를 근거로 최종 답변을 생성한다.
RAG가 중요한 이유는, RAG 없이 LLM이 학습 시점의 고정된 지식에 의존하면서 최신 정보나 특정 도메인 지식에 대해 틀리거나 그럴듯한 답을 만들어낼 수 있기 때문이다. 반대로 RAG는 외부 소스로부터 정확한 근거를 가져와 답변을 생성하게 만들어, 사실성(factuality)과 구체성을 높인다.

다만 사람 손으로 매번 관련 문서를 찾아 복사해 붙이는 방식은 확장 가능하지 않다. 따라서 실제 AI 앱에서는 사용자의 질문에 맞는 정보를 자동으로 검색하고, 필요한 만큼만 컨텍스트로 구성한 뒤, 그 기반 위에서 답변을 생성하는 시스템이 필요하다.
##### 관련 문서 검색
AI 앱의 RAG 시스템은 기본적으로 세 단계를 거친다 : 
- Indexing : 외부 데이터 소스를 로드/전처리하고 chunk로 분할한 뒤, 각 chunk의 embedding과 메타데이터를 vector store에 저장한다.
- Retrieval : 사용자의 query를 embedding으로 변환하고, vector store에서 유사도 기반 Top-k 검색을 통해 관련 chunk(Document)를 가져온다. 이때 k가 커질수록 속도/비용이 증가하고 노이즈가 섞일 수 있어 적절한 균형이 필요하다.[^1]
- Generation : 검색된 chunk를 `{context}`로 프롬프트에 주입해 LLM을 호출하고, LLM은 해당 컨텍스트를 근거로 최종 답변을 생성한다. 이 흐름은 `prompt | llm` 같은 체인으로 합성할 수 있고, runnable로 캡슐화해 질문 하나로 'retrieve 후 generate'를 재사용 가능하게 만들 수 있다
##### 실습
###### 0. 설정
`text.txt` 파일의 내용은 [[Resources/books/Learning LangChain/1. LLM Fundamentals with LangChain\|1장]] 내용으로 넣어두었다.
```python
TEST_FILE = os.getenv("RAG_TEST_FILE", "./text.txt")

# psycopg3 드라이버
PG_CONN = os.getenv(
    "PGVECTOR_CONN",
    "postgresql+psycopg://langchain:langchain@localhost:6024/langchain",
)

COLLECTION_NAME = os.getenv("PGVECTOR_COLLECTION", "rag_demo_docs")

EMBED_MODEL_NAME = os.getenv("EMBED_MODEL", "text-embedding-3-large")
```

###### 1. Indexing : Load + Split
```python
def load_and_split(file_path: str) -> List[Document]:
    """문서 로드 + 청크 분할"""
    raw_docs = TextLoader(file_path, encoding="utf-8").load()

    splitter = RecursiveCharacterTextSplitter(
        chunk_size=1000,
        chunk_overlap=200,
    )
    chunks = splitter.split_documents(raw_docs)

    # 디버깅 편의용 메타데이터
    for i, d in enumerate(chunks):
        d.metadata = {**d.metadata, "chunk_id": i, "source_file": file_path}
    return chunks
```
###### 2. Indexing : Embed + Store
```python
def build_vector_store(docs: List[Document]) -> PGVector:
    """
    PGVector.from_documents를 사용하면,
    - 컬렉션 생성
    - (옵션) 기존 컬렉션 삭제
    - 문서 임베딩 + 저장
    """
    embeddings = OpenAIEmbeddings(model=EMBED_MODEL_NAME)

    # 버전에 따라 인자가 connection / connection_string 으로 다를 수 있어 둘 다 대응
    try:
        db = PGVector.from_documents(
            documents=docs,
            embedding=embeddings,
            connection=PG_CONN,              
            collection_name=COLLECTION_NAME,
            pre_delete_collection=True,          # 노트북 재실행 시 깔끔
            use_jsonb=True,
        )
    except TypeError:
        db = PGVector.from_documents(
            documents=docs,
            embedding=embeddings,
            connection_string=PG_CONN,           # 일부 구현/버전 스타일
            collection_name=COLLECTION_NAME,
            pre_delete_collection=True,
            use_jsonb=True,
        )

    return db
```
###### 3. Retrieval
```python
def retrieve_only(db: PGVector, query: str, k: int = 3) -> List[Document]:
    """Retrieval 단계만 실행"""
    retriever = db.as_retriever(search_kwargs={"k": k})
    return retriever.invoke(query)


def format_docs(docs: List[Document]) -> str:
    """LLM 컨텍스트로 넣기 좋은 문자열로 변환"""
    blocks = []
    for d in docs:
        meta = d.metadata
        blocks.append(
            f"[source={meta.get('source_file')}, chunk_id={meta.get('chunk_id')}]\n{d.page_content}"
        )
    return "\n\n---\n\n".join(blocks)
```
###### 4. `@chain` 기반 Runnable(RAG)
컨텍스트가 질의마다 바뀌기 때문에, 'Retrieval→Prompt 구성→LLM 호출'을 하나의 runnable(`make_qa_runnable`)로 묶어 매번 동적으로 실행한다
```python
def make_qa_runnable(db: PGVector, k: int = 3):
    """
    질문(문자열) 하나를 넣으면:
    - 관련 문서 검색(retrieve)
    - 프롬프트 구성(format + inject context)
    - LLM 호출(generate)
    까지를 한 번에 수행하는 Runnable을 만든다.
    """
    retriever = db.as_retriever(search_kwargs={"k": k})

    prompt = ChatPromptTemplate.from_messages(
        [
            (
                "system",
                "You are a helpful assistant. Use the provided context to answer the question.\n"
                "If the context does not contain the answer, say you don't know.\n",
            ),
            ("human", "Question:\n{question}\n\nContext:\n{context}\n"),
        ]
    )

    llm = ChatOpenAI(model=CHAT_MODEL_NAME, temperature=0)
    parser = StrOutputParser()

    # prompt | llm | parser 는 “문자열 답변”을 내는 체인
    answer_chain = prompt | llm | parser

    @chain
    def qa(question: str) -> Dict[str, Any]:
        # 1) retrieve
        docs = retriever.invoke(question)

        # 2) format context
        context = format_docs(docs)

        # 3) generate answer
        answer = answer_chain.invoke({"question": question, "context": context})

        # (선택) 디버깅/검증을 위해 docs도 함께 반환
        return {"answer": answer, "docs": docs}

    return qa
```
###### 실행
```python
docs = load_and_split(TEST_FILE)
print(f"[Indexing] loaded & split into {len(docs)} chunks")

db = build_vector_store(docs)
print(f"[Indexing] stored into PGVector collection = {COLLECTION_NAME}")

query = "이 문서의 핵심 주제를 한 문장으로 요약해줘."

# Retrieval 단계만 먼저 확인
retrieved = retrieve_only(db, query=query, k=3)
print("\n[Retrieval] top-3 chunks:")
for d in retrieved:
    print(f"- chunk_id={d.metadata.get('chunk_id')} len={len(d.page_content)}")

# @chain runnable로 RAG 실행
qa = make_qa_runnable(db, k=3)
out = qa.invoke(query)

print("\n[Generation] answer:")
print(out["answer"])

print("\n[Debug] docs returned:")
for d in out["docs"]:
    print(f"- chunk_id={d.metadata.get('chunk_id')} source={d.metadata.get('source_file')}")
```
